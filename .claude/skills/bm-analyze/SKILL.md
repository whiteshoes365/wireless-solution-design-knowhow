# 경쟁사 무선모듈 벤치마킹(BM) 분석 스킬

이 스킬은 무선모듈 지식 사이트(`proc-benchmark` 섹션)의 BM 프레임을 실제 분석에 적용한다.
목적은 **스펙 나열이 아니라 인사이트·액션 도출**이다. 데이터는 수단, 인사이트가 결과물.

## 0. 시작 전 — 보안·윤리 (반드시 먼저 확인)

- **경쟁사 분석 데이터·측정값·teardown 결과는 사내/로컬 전용.** 공개 저장소(GitHub Pages 등)에 커밋·업로드하지 말 것.
- 결과물은 프로젝트 루트가 아닌 **`bm-output/`(gitignore 권장) 또는 사내 문서**로 저장.
- 벤치마킹은 **원리·방향 학습**이지 설계 카피가 아니다. 특허·영업비밀 침해, 회로 무단복제 금지.
- 원가·내부구조는 대부분 **추정(estimate)** 이다. 결과에 반드시 "실측/추정"을 구분 표기.

## 1. 입력 수집

사용자가 준 자료를 먼저 확인하고, 부족하면 무엇이 있는지 묻는다:

- **대상**: 자사 모듈 1 + 경쟁 모듈 1~N (모델명·벤더)
- **자료 유형**(있는 것만): ①데이터시트(스펙) ②teardown(분해 사진·BOM·칩 마킹) ③측정값(Tx출력·감도·전류·OTA) ④PCB 정보(층수·크기·재료) ⑤원가/구성 추정
- 각 값의 **측정 조건**(온도·채널·전압·치구)을 함께 확보 — 없으면 "조건 불명"으로 표기

> 자료가 전혀 없으면: 어떤 형태의 자료를 줄 수 있는지 물어보고, 그때까지는 빈 템플릿만 생성한다.

## 2. 분석 축 (자사·경쟁 동일 잣대로)

다음 8축을 기준으로 사실을 추출한다(사이트 BM 섹션과 동일):

| 축 | 무엇을 보나 |
|---|---|
| RF 성능 | Tx 출력·수신감도·EVM·OTA(TRP/TIS) |
| 전력 | Tx/Rx/Sleep 전류, 절전(TWT·듀티) |
| BOM·원가 | 부품 수·통합도·추정 단가(상대) |
| 부품 구성 | 칩(벤더)·FEM·발룬·필터·안테나 방식 |
| PCB | 층수·재료·크기·스택업 |
| 안테나 | 방식(칩/PCB/FPC/판금/LDS)·배치·효율 |
| 인증·지역 | 지원 대역·지역 커버·출력 한계 |
| 열·기구 | 쉴드캔·방열·기구 결합 |

## 3. 정규화 (비교 가능하게)

- 측정 조건이 다르면 비교 무효 → **같은 조건 기준**으로만 나란히 놓는다. 불일치는 명시.
- 절대값이 불확실하면 **상대 지수(자사=100)** 로 표기.
- 정성 항목(안테나 방식 등)은 표로, 정량 항목은 수치로.

## 4. 산출물 A — 비교 장표

아래 형식의 표를 만든다(값은 자료에서 채우고, 없으면 `?`/`추정`):

| 항목 | 자사 | 경쟁 A | 경쟁 B | Gap / 시사점 |
|---|---|---|---|---|
| Tx 출력(dBm) | | | | |
| 수신감도(dBm) | | | | |
| Sleep 전류(µA) | | | | |
| 부품 수 / 통합도 | | | | |
| 추정 BOM(자사=100) | | | | |
| PCB 층수 / 크기 | | | | |
| 안테나 방식 | | | | |
| 지원 규격/세대 | | | | |

각 행 값 옆에 **(실측)/(추정)/(데이터시트)** 출처를 괄호로.

## 5. 산출물 B — So-What 인사이트 (핵심)

Gap마다 아래 5단으로 밀어붙인다. **Why(원인)까지 파야 카피가 아닌 우리 액션이 나온다.**

| Fact(사실) | Gap(차이) | Why(원인 추정) | Insight(시사점) | Action(실행) |
|---|---|---|---|---|
| 예) 경쟁 감도 −3dB 우수 | 3dB | 외장 LNA + FPC 안테나 | 감도=거리 경쟁력 | 차기 LNA·안테나 방식 재평가 |

- 최소 3개, 임팩트 큰 순으로 정렬.
- Why는 **추정임을 명시**(단정 금지).

## 6. 산출물 C — 요약 (결론 먼저)

- 맨 위에 **한 줄 결론 + 상위 3개 액션**(경영/설계 의사결정용).
- 그 다음 근거(비교표·So-What).
- 마지막에 **데이터 공백**(추가로 측정/확보해야 할 항목) 목록.

## 7. 출력 형식 선택

사용자에게 묻거나 기본값 사용:

- **기본**: 한국어 Markdown 리포트를 `bm-output/BM_<대상>_<날짜>.md` 로 저장(로컬 전용).
- **옵션**: 지식 사이트의 *사내 사설 복제본*에 붙일 `content.js` 블록 스니펫(표/So-What) 생성.
  - 형식: `{ t:"table", head:[...], rows:[[...]] }`, So-What도 table 블록.
  - ⚠️ 공개 저장소(pages)에는 붙이지 말 것 — 사내 로컬 복제본에만.

## 8. 진행 절차 요약 (이 순서로 실행)

1. 보안·윤리 확인(0) → 저장 위치를 `bm-output/`로 안내
2. 입력 수집·부족분 질의(1)
3. 8축으로 사실 추출(2) + 조건 정규화(3)
4. 비교 장표(4) → So-What(5) → 요약·결론 먼저(6)
5. 날짜 계산은 `date` 명령으로(추측 금지), 결과 파일에 날짜 기입
6. 출력 형식대로 저장(7), 데이터 공백·다음 액션 제시

## 체크리스트 (완료 전 확인)

- [ ] 자료 출처를 (실측/추정/데이터시트)로 구분 표기했는가
- [ ] 측정 조건 정규화하고 불일치를 명시했는가
- [ ] 모든 Gap에 Why→Insight→Action을 붙였는가
- [ ] 결론(상위 액션)을 맨 앞에 뒀는가
- [ ] 결과를 로컬(`bm-output/`)에 저장, 공개 저장소엔 미커밋인가
- [ ] 데이터 공백(다음 측정 항목)을 정리했는가
